Operations

AI assistants (MCP)

Connect Claude or Cursor to your Dockyrd panel so an assistant can read deploy status, logs and analytics, trigger deploys, and help change projects and services — with the same permissions as your team account.

Pre-release MCP is specified in the repository (ADR-0002) ahead of the first shipped build. Until your version includes /mcp, use the dy CLI and API tokens for automation.

What you get

CapabilityTypical use
Deployments and build output“Why did this deploy fail?”
Runtime and access logsTrace errors after a release
Analytics and server metricsTraffic and capacity questions
Manual deployRedeploy after a config change
Projects and servicesNaming, build settings, domains (within your role)
Instance settingsDomains, SMTP, security (admins; secrets never returned to the model)

How it works

Dockyrd runs the MCP server inside the same dockyrd process as the dashboard.

  • Remote clients (Claude, Cursor): Streamable HTTP at https://YOUR_PANEL/mcp, with OAuth 2.1 sign-in through the panel (PKCE, MFA when required).
  • Same machine as the server: optional dockyrd mcp --stdio with an API token in the environment.

The planned Settings → Integrations → AI assistants page walks through OAuth and shows your MCP URL.

Connect Cursor

  1. Open Settings → Integrations → AI assistants and choose Connect Cursor.
  2. Sign in in the browser (including 2FA if prompted).
  3. Approve scopes (read, deploy, write as needed).

Cursor stores the access token and uses POST https://YOUR_PANEL/mcp with Streamable HTTP. Prefer OAuth over pasting long-lived tokens into committed config files.

Connect Claude

Add your panel as a remote MCP server in Claude Code or Claude Desktop. On first use, Claude discovers authorization at /.well-known/oauth-protected-resource and opens the panel login. Use your production HTTPS URL, not plain HTTP.

Scopes and roles

OAuth scopeMeaning
mcp:readViewer+: lists, logs, analytics
mcp:deployMember+: trigger deploys and restarts
mcp:writeMember+: create or patch projects and services
mcp:instance:readAdmin+: instance settings (no secrets in tool output)

Local stdio on the server

export DOCKYRD_URL="https://panel.example.com"
export DOCKYRD_TOKEN="dyk_…"
dockyrd mcp --stdio

Create the token under Settings → Account → API tokens with the right project and scope. For laptops talking to a remote VPS, prefer HTTPS + OAuth instead of stdio.

Security

  • Prefer OAuth for Claude and Cursor on your workstation.
  • Revoke connections from Integrations or delete API tokens you no longer need.
  • Do not expose the panel on plain HTTP in production.

See also Users & security and the CLI reference.
